COMPREHENSIVE PROJECT REPORT

CampusConnect - MERN Stack Web Development



1 Introduction

1.1 Project Overview

The primary objective of this project is to design, develop, and deploy a unified smart campus platform named CampusConnect. Built utilizing the MERN (MongoDB, Express.js, React.js, Node.js) stack, this application aims to digitize campus communication, manage college events securely, and foster an interactive student-faculty community. Traditional educational institutions often rely on highly fragmented communication systems (notice boards, WhatsApp groups). CampusConnect solves this by providing a centralized digital hub featuring Role-Based Access Control (RBAC), enabling administrators to post announcements and manage events, while students can register for events, participate in discussion forums, and access academic resources.

2 Requirements Analysis

2.1 Hardware Requirements

  • Processor: Intel Core i3 / AMD Ryzen 3 or equivalent (Minimum); Intel Core i5 (Recommended)
  • RAM: 4GB (Minimum); 8GB (Recommended)
  • Storage: 1GB free disk space for local environment setup
  • Internet: High-speed internet connection required for cloud database (MongoDB Atlas) and deployment.

2.2 Software Requirements

  • Operating System: Windows 10/11, macOS, or Linux (Ubuntu 20.04+)
  • Runtime Environment: Node.js (v18.x or higher)
  • Package Manager: npm (v9.x or higher)
  • Code Editor: Visual Studio Code (VS Code)
  • Database Server: MongoDB Atlas (Cloud)

2.3 Functional Requirements

  • The system must allow users to register and log in securely.
  • The system must support distinct roles for 'Students' and 'Administrators'.
  • Administrators must be able to create, edit, and delete campus events and announcements.
  • Students must be able to view and register for events.
  • Users must be able to create community discussion threads and reply to posts.
  • The system must allow image uploads for profile pictures and event banners.

2.4 Non-Functional Requirements

  • Security: All passwords must be hashed before database insertion. API routes must be protected using JSON Web Tokens (JWT).
  • Performance: Database queries should be paginated to reduce memory overhead during large data retrievals.
  • Usability: The frontend must be fully responsive across mobile, tablet, and desktop devices.

3 System Design

3.1 System Architecture

The application implements a robust Three-Tier Architecture model:

  • Client Tier (Frontend): A Single Page Application (SPA) built with React.js. It manages UI rendering, client-side routing, and global state management via the Context API.
  • Server Tier (Backend): An Express.js REST API that intercepts HTTP requests, enforces Zod schema validation, handles business logic, and manages JWT authentication.
  • Data Tier (Database): MongoDB serves as the NoSQL storage layer, interacting with the backend via Mongoose ORM. Cloudinary is utilized as an external cloud storage provider for handling media files.

3.2 Database Design

The database is structured using Mongoose Schemas. Below is the structure for the core entities:

  • User Entity: name, email (unique), password (hashed), role (enum), college, department, profilePicture.
  • Event Entity: title, description, date, location, feeType, feeAmount, createdBy (Reference to User).
  • Discussion Entity: title, content, category, author (Reference to User), replies array.

4 Technology Stack

4.1 MongoDB

MongoDB is a NoSQL document database used for its high-volume data storage capabilities and flexibility. Data is stored in JSON-like documents with dynamic schemas, making data integration seamless in MERN applications.

4.2 Express.js

Express is a minimal and flexible Node.js web application framework that provides a robust set of features. It acts as the backend routing framework, handling HTTP requests, and integrating Zod validation middleware.

4.3 React.js

React is a declarative, efficient, and flexible JavaScript library for building user interfaces. Using Vite as the build tool, the frontend operates as a SPA, utilizing React Router DOM for instant page transitions without browser reloads.

4.4 Node.js

Node.js is an asynchronous event-driven JavaScript runtime designed to build scalable network applications. It powers the Express server and allows JavaScript to execute on the server-side.

4.5 Other Tools / Libraries

  • Mongoose: Object Data Modeling (ODM) library for MongoDB.
  • Zod: Schema declaration and validation library to sanitize API inputs.
  • Cloudinary & Multer: Used for secure cloud image uploading and streaming.
  • Bcryptjs & JWT: Used for password hashing and secure stateless authentication.

5 System Implementation

5.1 Module 1: Authentication & Authorization

Handles secure user registration and login using `bcryptjs` for password hashing and `jsonwebtoken` (JWT) for session management. Includes distinct Role-Based Access Control (RBAC) for 'Students' and 'Admins'. Admin registration is guarded by a confidential server-side secret key.

5.2 Module 2: Interactive Dashboard

A centralized UI providing users with a quick overview of upcoming events, recent announcements, and quick-action navigation. It dynamically fetches and renders data based on the authenticated user's role.

5.3 Module 3: Event Management

Allows administrators to create, read, update, and delete campus events. Features server-side pagination (using MongoDB `.skip()` and `.limit()`) to optimize database load and network bandwidth.

5.4 Module 4: Community Discussions

A forum system for students and faculty to post queries and share resources categorized by Academics, Placements, and General queries. Users can engage in threaded conversations.

5.5 API / Backend Implementation - code

Below is the implementation of the backend Validation Middleware and Authentication Controller:

// Zod Validation Middleware (middleware/validate.js)
const { ZodError } = require('zod');
const validate = (schema) => (req, res, next) => {
    try {
        schema.parse(req.body);
        next();
    } catch (err) {
        if (err instanceof ZodError) {
            const errors = err.errors.map(e => `${e.path.join('.')}: ${e.message}`);
            return res.status(400).json({ message: 'Validation Failed', errors });
        }
        res.status(500).json({ message: 'Internal Server Error' });
    }
};

// Event Pagination Controller (controllers/eventController.js)
const getEvents = async (req, res) => {
    const page = parseInt(req.query.page, 10) || 1;
    const limit = parseInt(req.query.limit, 10) || 10;
    const skip = (page - 1) * limit;

    const totalEvents = await Event.countDocuments();
    const events = await Event.find().skip(skip).limit(limit).sort({ date: 1 });
    
    res.json({ events, currentPage: page, totalPages: Math.ceil(totalEvents / limit) });
};

5.6 Frontend Implementation - code

Below is the implementation of the React Context API for global state and data fetching:

// Frontend Auth Context (context/AuthContext.jsx)
import { createContext, useState, useEffect } from 'react';

export const AuthContext = createContext();

export const AuthProvider = ({ children }) => {
    const [user, setUser] = useState(null);
    const [token, setToken] = useState(localStorage.getItem('token') || '');

    const login = (userData, jwtToken) => {
        setUser(userData);
        setToken(jwtToken);
        localStorage.setItem('token', jwtToken);
    };

    const logout = () => {
        setUser(null);
        setToken('');
        localStorage.removeItem('token');
    };

    return (
        <AuthContext.Provider value={{ user, token, login, logout }}>
            {children}
        </AuthContext.Provider>
    );
};
